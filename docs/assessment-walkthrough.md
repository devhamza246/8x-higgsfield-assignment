# Assessment walkthrough — target 4 minutes

Record with camera on and voiceover. Separately record the one-minute introduction
with personal details that are true and not already on your CV. Do not imply you
implemented live inference, server billing, support services or cloud persistence.

## 0:00–0:35 — Product decision

“I focused on a creator making a short product film. Rather than reproduce the
whole marketplace, I made the cost, project limit and recovery part of creating.
Higgsfield already has cost displays and technical-failure refunds; my change
brings them together and adds a hard project-level limit.”

Mention the initial public-product research and its limitations. Avoid unverified
review counts, claims of statistically proven pain, or invented user interviews.

## 0:35–1:30 — Creative loop

Open the public URL, with no login. Explain Demo mode immediately. Show the preview,
looks, priority, aspect ratio, duration and changing credit quote. Edit the brief
and attach a local reference. Explain that bundled sample content is unchanged.
Start a sample; show the reserved balance and the ability to cancel while queued.

## 1:30–2:20 — Recovery and control

Enable “Make the next sample fail”, run a sample and show the ledger credit return.
Lower the project limit to already committed usage and attempt another sample:
show rejection with no deduction. Raise the limit to continue.

## 2:20–3:15 — Useful completion

Play a completed film, compare a second look, approve a result, refresh to show saved
history and download a matching sample MP4. Show that project budgets are separate
while the demo balance is shared.

## 3:15–4:00 — Engineering and cuts

Point to pure state transitions and transaction tests: duplicate active requests,
invalid inputs, balance/budget limits, exactly-once returns and refresh continuation.
Explain cross-tab locking and local storage. Explain cuts: accounts, payments,
model APIs, community, character training and a timeline editor. Next step is a
provider adapter with authoritative server job state, not more decorative pages.

## Before submission

Verify the deployed URL in a signed-out browser, GitHub repository public visibility,
latest implementation and `.agent-logs/` pushed, camera on, walkthrough under five
minutes, intro video recorded, and all links labelled. Deployment privacy and
repository visibility must be verified separately; a private preview is not enough.
